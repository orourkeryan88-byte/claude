RELIER · Implementation

Building the three systems in HighLevel

Build order matters — each phase depends on the one before it. Custom fields before forms, forms before workflows, everything before you turn it on. Roughly a day and a half if you don't stop.

Settle this before you build anything

Irish SMS replies. Half the messages in System 4 ask him to reply — "reply Y", "reply YES". That only works from a long number your contact can text back. If HighLevel routes Irish traffic through an alphanumeric Sender ID (a name, not a number), replies are impossible and the whole confirmation mechanic silently dies.

So before phase 1: go to Settings → Phone Numbers → Add Number and try to buy an SMS-capable +353 mobile number. If none is available, buy a UK +44 mobile number — Irish handsets treat it as a normal number and replies work. Send yourself a test and reply to it. If you can't get two-way SMS, tell me and I'll rewrite the sequences to use email replies and click-tracking instead.

Phase 0 Foundations

~45 min

Build everything inside a sub-account, never the agency view. When it works you snapshot it, and every future client build starts from that snapshot.

Create the sub-account

Agency view → Sub-Accounts → Create Sub-Account — name it RELIER — Internal. This one runs your own agency's pipeline. Client sub-accounts come later.

Business profile

Settings → Business Profile — set Timezone to Europe/Dublin before you touch a calendar. Get this wrong and every reminder fires at the wrong hour, and fixing it afterwards means rebuilding the wait steps.

Email sending

Settings → Email Services — connect a sending domain. Use a subdomain like mail.relier.ie, never your root domain: if deliverability tanks, your main domain survives. Add the SPF, DKIM and DMARC records at your registrar and wait for them to verify green before sending anything.

Custom Values — do this now, thank yourself later

Settings → Custom Values. These are global variables you reference as {{custom_values.name}} in any email, SMS or workflow. Set them once; change the VSL link in one place instead of eleven.

Phase 2 Forms, calendars, contract

~2 hrs

Form 1 — Sales Intake (internal, you fill it in)

Sites → Forms → Builder → + Add Form — name it Sales Intake.

Drag in every custom field from phase 1, plus first name, last name, email, phone. Mark Signatory Email, Package, Management Fee, Ad Spend Budget, Start Date and Territory Granted as required — this form generates the contract and a blank field means a broken contract.

Under form settings set On Submit → Show message, not redirect. You're filling this in on Zoom while he watches; a redirect is a distraction.

Form 2 — Onboarding Discovery

Same builder, name it Onboarding Discovery. Use the questionnaire from onboarding/templates/02, trimmed to what matters for a trade firm.

Make these two fields required

"Paste 3–5 real customer quotes, word for word" (multi-line) and "What number defines success in 90 days" (single line). Everything else can be optional. If those two come back empty you have no ad copy and no target, and the account starts blind.

Calendar 1 — Sales Call

Calendars → Calendar Settings → Create Calendar → Simple

NameSales Call — 20 min
Duration20 minutes, 15-minute gap between
AvailabilityMon–Fri. Include 7–9am and 5–7pm — trade owners are on site 9 to 5
Minimum notice2 hours
Booking window10 days out maximum. Longer bookings no-show more
ConfirmationTurn the built-in notifications OFF. Your workflow handles all of it

That last row matters. Leave GHL's default calendar notifications on and your prospect gets two confirmation emails, one of them generic.

Calendar 2 — Onboarding Call

Same, 45 minutes, built-in notifications off, booking window 14 days.

The contract template

Payments → Documents & Contracts → Templates → New Template

Name it RELIER Service Agreement. Build the body from onboarding/templates/07-service-agreement.md, and insert your custom fields as merge tags so it auto-populates: {{contact.trading_name}}, {{contact.management_fee}}, {{contact.territory_granted}}, {{contact.start_date}}.

Add a signature element and set the recipient to the Signatory Email field.

Before you send this to a human

Section 13 of that template is a structure for a solicitor, not a finished contract. Get an Irish solicitor to review it once — an hour of their time, and it covers every client you ever sign.

Phase 3 The workflows

~4 hrs

Seven workflows. Build them in this order — later ones depend on tags earlier ones apply. All via Automation → Workflows → Create Workflow → Start from Scratch.

Sales Call — Confirm & RemindWF-01 · System 4
Trigger
Customer Booked Appointment → filter Calendar = Sales Call
Steps
  1. Send Email — the confirmation email. Subject: You're booked in for {{appointment.start_time}} — two quick things
  2. Wait → Time Delay → 5 minutes
  3. Send SMS — the initial SMS
  4. Add Tag → stage-booked
  5. Update Opportunity → stage Call Booked
  6. Wait → Appointment Time → 24 hours before
  7. Send SMS — "Still good for tomorrow?" · then Send Email — the 24hr email with the local Ad Library fact
  8. Wait → Appointment Time → 1 hour before → Send SMS with the Zoom link
  9. Wait → Appointment Time → 5 minutes before → Send SMS "Starting now"
Watch for
Wait steps must be Appointment Time based, not time delays. A delay counts from booking; if he books 40 minutes before the call, a "24 hours before" delay never fires at all.
Confirmation Reply CatcherWF-02 · System 4
Trigger
Customer Replied → filter Reply Type = SMS
Steps
  1. If/Else — message body contains Y or YES
  2. True branch → Add Tag confirmed-yes → Internal Notification to you
  3. False branch → Internal Notification "Reply needs a human"
Why
Anyone without confirmed-yes at the 24-hour mark is your no-show risk. Filter the contact list on that tag the morning of, and ring them.
VSL WatchedWF-03 · System 4
Setup
First create a Trigger Link at Marketing → Trigger Links pointing at your VSL. Use that link in every email instead of the raw URL.
Trigger
Trigger Link Clicked → your VSL link
Steps
  1. Add Tag → vsl-watched
  2. Internal Notification — "{{contact.first_name}} just watched the VSL"
Why
A click isn't a watch, but it's the only signal you get. Someone who clicked and books is a different call from someone who didn't — and the notification lets you ring while it's fresh.
No-Show RecoveryWF-04 · System 4
Trigger
Appointment Status → status No Show → filter Calendar = Sales Call
Steps
  1. Add Tag stage-noshow
  2. Wait 10 minutes → Send SMS — "No bother, things come up on site"
  3. Wait 3 hours → Send Email — the VSL and rebook link
  4. Wait 3 days → Send SMS · Wait 7 days → Send Email
Watch for
This only fires if the appointment is marked No Show. Either mark it yourself straight after the call, or set the calendar to auto-mark — otherwise a third of your pipeline sits there untouched.
Intake → ContractWF-05 · System 2
Trigger
Form Submitted → Sales Intake
Steps
  1. Add Tag stage-won · Update Opportunity → Won — Intake Pending
  2. Send Document/Contract → template RELIER Service Agreement → recipient {{contact.signatory_email}}
  3. Send Email — the welcome-aboard email that restates the terms in plain English
  4. Internal Notification → "NEW CLIENT: {{contact.trading_name}}, {{contact.management_fee}}/mo, starts {{contact.start_date}}"
  5. Wait 48 hours → If/Else: contract still unsigned → Send SMS "Did that contract come through alright?"
Watch for
Step 5 is the one people skip and it's the most valuable step in the workflow. Unsigned contracts go cold in about three days.
Contract Signed → OnboardingWF-06 · System 2
Trigger
Documents & Contracts → filter Status = Completed, Template = RELIER Service Agreement
Steps
  1. Add Tag client-onboarding · Update Opportunity → Contracted
  2. Send Email — "Signed, here's the only homework you'll get" with the onboarding form link and the photo ask
  3. Create Task — "Set up {{contact.trading_name}} workspace", assigned to you, due in 1 day
  4. Internal Notification to the team
  5. Wait 3 days → If form not submitted → Send SMS nudge
Onboarding Form → Calendar → RemindersWF-07 · System 2
Trigger
Form Submitted → Onboarding Discovery
Steps
  1. Update Opportunity → Onboarding
  2. Send Email — "Last step, pick a time" with the onboarding calendar link
  3. Send Email — the platform access checklist
  4. Create Tasks — the 14-day launch checklist, assigned with due dates
Then
A second workflow triggered by Customer Booked Appointment → Calendar = Onboarding Call runs the 24hr / 1hr / 5min ladder. Same shape as WF-01, warmer copy — he's a client now, not a prospect.

Cut it here if you're short on time

WF-05 and WF-06 alone solve 80% of the buyer's-remorse problem — contract auto-sends on intake, onboarding form auto-sends on signature. Build those two, run a client through them, then come back for the rest. Building all seven before your first client is how people spend three weeks in HighLevel and never make a call.

Phase 4 Test before anyone real touches it

~45 min

Create a contact with your own mobile and a spare email address. Run the entire chain end to end. Every agency that skips this sends a client an email addressed to {{contact.first_name}}.

0%0 / 0

Then snapshot it

Agency view → Snapshots → Create Snapshot from the sub-account. That freezes the whole build — fields, forms, calendars, workflows, pipeline — and every future client sub-account loads from it in about ninety seconds. This is the point where the day and a half you just spent starts paying you back.

Next What this doesn't cover

System 1's ad side. HighLevel can't run your Meta ads. Connect the account at Settings → Integrations → Facebook so lead-form leads flow in, but build and manage campaigns in Ads Manager.

The DM conversation. Connect Instagram and Facebook Messenger under Integrations and every DM lands in Conversations. Do not automate the qualifying questions — the whole point is that it reads like a person. Automate only the first reply, then take over.

Client-facing sub-accounts. Everything above is RELIER's own pipeline. Once you sign a trade firm, spin them a sub-account from a different snapshot — one built around their lead flow, not yours. That's a separate build, and worth doing after client one, not before.
